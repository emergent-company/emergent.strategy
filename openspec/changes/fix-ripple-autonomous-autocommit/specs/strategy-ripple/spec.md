## MODIFIED Requirements

### Requirement: Convergence Loop

The system SHALL run a convergence loop after every `commit_batch` that
iteratively detects misalignments and stages fixes for autonomous-tier
signals for human review, continuing until equilibrium is reached or damping
limits are hit.

#### Scenario: Detection-only mode (agent-orchestrated)

- **WHEN** the convergence loop runs without a `SignalResolver`
- **THEN** it detects signals, classifies authority tiers, computes equilibrium,
  and returns the result without modifying any artifacts
- **AND** the `convergence_summary` in the commit response tells the agent
  what needs attention

#### Scenario: Resolution mode (server-orchestrated)

- **WHEN** the convergence loop runs with a `SignalResolver`
- **THEN** it calls the resolver for each autonomous-tier signal and stages
  each resulting fix as a mutation, grouped under a single batch shared by all
  fixes produced within that convergence run
- **AND** it tracks cumulative change distance for damping and re-senses
- **AND** no artifact's live content is modified by this process

#### Scenario: Signal authority classification

- **WHEN** the loop classifies signals for the resolver
- **THEN** structural signals (orphan, staleness, clustering) at warning or
  info severity are classified as `autonomous`
- **AND** semantic signals (drift, tension, propagation) use severity-based
  escalation: info → autonomous, warning → gated, critical → escalated

#### Scenario: Signal deduplication

- **WHEN** the loop creates new signals
- **THEN** it checks for existing active signals with the same (source_key,
  target_key, signal_type) and skips duplicates
- **AND** this prevents signal accumulation across iterations

#### Scenario: Autonomous-tier signals remain active pending review

- **WHEN** a fix for an autonomous-tier signal is staged
- **THEN** the signal's status remains `active`, not `resolved`
- **AND** it is resolved only when a human commits the staged batch, via the
  same post-commit resolution that resolves any other signal on commit

### Requirement: Autonomous Commit Path

Despite its name (kept for continuity with the mutation `source` value,
`ripple_auto`, and existing tooling that filters by it), this path no longer
commits anything autonomously. The system SHALL stage fixes generated for
autonomous-tier signals rather than committing them to live state directly.
No content change generated by the convergence loop's resolver SHALL become
part of an instance's current state without a human explicitly committing it
— there is no tier, including `autonomous`, that bypasses this.

This exists because the authority tier is derived from a similarity score
(embedding-based or, without Memory, word-overlap), which is unable to
distinguish a trivial rewording from a meaning-inverting edit. Skipping human
review entirely on that basis is not a safe optimization.

#### Scenario: Auto-commit a fix

- **WHEN** the resolver generates a fix for an autonomous-tier signal and
  damping checks pass
- **THEN** the fix is staged as a mutation with `status='staged'`,
  `source='ripple_auto'`, and the originating signal ID in `batch_metadata`
- **AND** current state is unchanged until a human commits the batch
- **AND** the strategic index is not derived until commit

#### Scenario: Auto-commit visibility

- **WHEN** a user lists mutations for an instance
- **THEN** ripple-generated mutations appear with `source='ripple_auto'` and
  are filterable by this source, whether staged or, once a human commits
  them, committed

#### Scenario: Auto-commit reversibility

- **WHEN** a human commits a previously-staged `ripple_auto` mutation and
  later calls `restore_version`
- **THEN** it is reverted along with all other state, exactly like any other
  committed mutation
- **AND** a mutation that was staged and then discarded, never committed,
  requires no reversal — it was never part of any state to revert

#### Scenario: Fixes from one convergence run share a batch

- **WHEN** a single convergence run stages fixes for more than one signal
- **THEN** all of them are staged under the same batch, reviewable and
  committable (or discardable) together

#### Scenario: A staged fix is visible without new tooling

- **WHEN** a convergence run stages a fix
- **THEN** the batch appears in the same pending-review surfaces (dashboard
  pending-review count, review inbox, draft-review page keyed by `batch_id`)
  used by every other staged batch in the system, with no ripple-specific
  review surface

#### Scenario: A discarded fix leaves the signal active

- **WHEN** a human discards a batch of ripple-staged fixes
- **THEN** the originating signals remain `active`
- **AND** no content generated by the discarded fix is applied anywhere

#### Scenario: Equilibrium auto-publish requires an actual commit

- **WHEN** equilibrium is reached as a result of fixes that were staged but
  not yet committed
- **THEN** no version is auto-published
- **AND** a version is auto-published only when a real commit — of the
  triggering batch or of a later human-approved staged batch — results in
  equilibrium
